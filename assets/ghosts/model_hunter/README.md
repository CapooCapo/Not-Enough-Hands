# Midnight Grin (Door Ghost)

`Meshy_AI_Midnight_Grin_biped/` is the 3D ghost of the Door Ghost Minigame,
wrapped for gameplay by `ghosts/door_ghost.tscn`.

## What the asset actually ships

| File | What it is |
|---|---|
| `..._Character_output.fbx` | Mesh + 24-bone rig. **Unused** — the file below is a strict superset. |
| `..._Meshy_AI_Meshy_Merged_Animations.fbx` | Same mesh and rig plus ten clips. This is the one instanced. |
| `..._texture_0_normal.png` | 2048² tangent-space normal map. The only texture in the download. |
| `Meshy_AI_Midnight_Grin_biped.zip` | The original download. Same three files, nothing more. |

Two facts about the import drive everything else here, both measured rather
than assumed:

- **It needs a 180° yaw, not an X correction.** Posed, the model stands 1.70 m
  with its feet on its own origin and looks along **+Z**; Godot's forward is
  −Z. `door_ghost.tscn` applies that yaw on the `Model` node.
- **Its rest pose is degenerate.** The Armature carries a −90° X rotation that
  the *animation data* cancels, so with nothing playing the rig lies flat on
  the floor. `DoorGhost.appear()` therefore always starts a clip.

Only `Idle_9`, `Unsteady_Walk` and `Walking` hold position. `Catching_Breath`
travels 5.6 m and `Dead` 0.95 m, so neither can be used on a ghost whose world
position is driven from code.

## Why the textures are baked

The import is **one** MeshInstance3D with **one** surface, **one** material,
**one** connected component, no vertex colours, and — confirmed by reading the
FBX string table — no material or texture references at all. Godot synthesises
a flat white `StandardMaterial3D` on import. Skin, eyes, teeth, hair, hoodie,
jeans and the knife are fused into that single surface.

So there is no material slot to tune per part and no island layout to paint
into. The only attribute that identifies a part *and* survives skinning is the
UV, so the parts are resolved into UV space once, offline, and shipped as a
normal albedo + ORM pair that a plain `StandardMaterial3D` uses at runtime:

- `midnight_grin_albedo.png` — base colour
- `midnight_grin_orm.png` — R = ambient occlusion, G = roughness, B = metallic

Both are generated by `tools/bake_midnight_grin_textures.gd`. Regenerate with:

```
godot --headless --script tools/bake_midnight_grin_textures.gd
godot --headless --editor --quit      # Godot will not notice the rewrite otherwise
```

`-- debug` bakes flat region colours instead, for checking the classification
on the model rather than inferring it from the finished skin.

### How a part is identified

- **Height bands** give shoes, jeans, hoodie and head their base colour. The
  bands are measured off the mesh (hoodie hem 0.855 m, jaw 1.395 m).
- **Thickness** finds the hair: one ray straight into the surface leaves a
  3 mm strand almost immediately and travels the width of a skull on a cheek.
  This is what darkens the lengths hanging *across* the face, which no band
  can reach. The crown and the back of the head are a solid shell, so they are
  taken by position instead.
- **Ambient occlusion**, ray traced against the model's own trimesh, darkens
  eye sockets, the mouth interior and the spaces between hair strands, and is
  also written to the AO channel.

Both probes need `ConcavePolygonShape3D.backface_collision` — they look at the
model from the inside as often as the outside, and without it every strand
reads as solid and every socket as unoccluded.

Curvature was tried first and does not work on this mesh: the triangulation is
uniformly lumpy, so normal divergence reads the same on a cheek as on a strand.
